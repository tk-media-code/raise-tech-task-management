## 実施内容

**バックエンド**（`DELETE /api/cards/{id}`）
- `CardService.delete` / `CardController.delete` を追加。204 No Content、アーカイブ済みでないカードは400、存在しないIDは404
- `card_label` の削除はDBの `ON DELETE CASCADE` に任せ、明示的な削除は行わない設計
- curlで正常系・異常系・冪等性・カスケード削除・CORSプリフライトを確認済み

**フロントエンド**
- `ArchivedCardItem.tsx` の「完全削除」ボタンを `disabled` プレースホルダーから実装へ置き換え（`useDelete` + `window.confirm`、ボード削除と同じ流儀）
- `CardDetailModal` には削除ボタンを置かない設計（アーカイブ済み限定という制約上、他画面から開くと常に押せないボタンになるため）
- `npm run lint` / `npm run build` 通過、ヘッドレスブラウザでの実操作検証（キャンセル時はリクエストが飛ばない、OK時に削除・空状態表示・詳細モーダルに削除ボタンが無いことまで確認）
- 検証で使った開発DBのダミーデータは `db/seed/dummy-data.sql` の再投入で元に戻し済み

**ドキュメント・要件定義**
- `docs/spring-boot/11-delete-api.md` に42章を追加、`docs/react/11-card-deletion.md` を新規作成（31〜32章）。両READMEのファイル構成表・目次も更新し、内部リンクは機械的に検証済み
- 要件定義（5.2・5.7）、画面定義（④・⑥）を実装内容に合わせて更新
